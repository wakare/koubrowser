# 多言語ローカライズ要件案

状態: L10N-1〜4 の基盤・移行・完了ゲートは実装済み。第 2 言語の公開には、
初期対応言語と翻訳レビュー体制の決定が必要。

## 背景

[Issue #18](https://github.com/yukikuri/koubrowser/issues/18) では多言語対応の要望があり、
[維持管理者の回答](https://github.com/yukikuri/koubrowser/issues/18#issuecomment-4818491772)
では「現状は多言語対応を考慮した作りになっておらず、まだ具体的には考えていない」
とされている。

現在は `src/common/locale.ts` に一部の日本語表示用定数があるが、これは翻訳カタログ
ではない。renderer 配下だけでも日本語を含む TypeScript/Vue ファイルが約 91 件あり、
候補行は約 1,566 行ある。ゲームから受け取る艦名・任務名なども含まれるため、文字列を
機械的に置換してはならない。

## 目的

- 甲ブラウザ自身が表示する文言を、選択した言語へ一貫して切り替えられるようにする。
- 日本語を完全な基準言語として維持し、翻訳欠落時にも操作不能や空欄を生じさせない。
- ゲーム由来の名称・本文と、アプリ由来の説明・状態・操作ラベルを明確に分離する。
- 翻訳追加時に TypeScript、レイアウト、アクセシビリティの回帰を自動検出する。

## 対象

### 翻訳する

- メイン画面、別ウインドウ、設定画面の操作ラベル、見出し、説明文
- loading、empty、error、retry、確認などのアプリ状態表示
- アプリ更新、保存、録画、スクリーンショット、データ保存先などの通知
- アプリが生成する任務指引、艦隊条件、戦闘・記録の補助説明
- aria-label、title、placeholder とキーボード操作案内
- Electron main process が生成するダイアログとエラーメッセージ

### 翻訳しない

- 艦これサーバーから受け取った艦名、装備名、任務名、敵艦隊名など
- DMM・艦これの Web ページ内容
- Wiki の引用、出典名、外部ページ本文
- ユーザーが付けた艦隊名、ページ名、パス、Proxy ルール
- ログ、DB、通信 payload に保存済みの原文

ゲーム由来の文字列に補助訳を表示する場合は、原文を必ず残し、別の審査済みデータと
して扱う。通常の UI 翻訳カタログへ混在させない。

## 言語モデル

- locale ID は BCP 47 形式を使う。基準言語は `ja-JP` とする。
- 初期の追加言語は維持管理者が決定する。Issue 投稿者の言語を推測して既定にしない。
- 未知または未対応の locale は `ja-JP` へフォールバックする。
- 初期値は既存動作を守るため `ja-JP` とする。OS 言語の自動選択は、対応言語が
  全画面で完成した後に別途判断する。
- 言語設定はアカウントではなくアプリ全体の `global.json` に保存する。
- main、main renderer、assist renderer、option renderer は同じ確定済み locale を使う。

## メッセージカタログ

- 安定した意味ベースの key を使い、日本語本文を key にしない。
- カタログは TypeScript から型検査できる静的データとし、実行時に外部コードを
  読み込まない。
- `ja-JP` の key 集合を正とし、他言語の欠落 key と余分な key をテストで拒否する。
- 変数埋め込みは名前付きパラメーターに限定し、HTML を翻訳値から注入しない。
- 数値、日時、相対時刻、単位、複数形は `Intl` を通す。既存記録の保存形式は変えない。
- 同じ日本語でも意味が異なる場合は別 key にする。翻訳者向けコメントに画面、意味、
  変数、文字数制約を記録する。
- 内部エラーの詳細はログに残し、利用者向け文言は安定した翻訳 key へ対応付ける。

## 実装境界

1. `src/common`
   - locale ID、メッセージ key、fallback、純粋な書式化関数を持つ。
   - Electron や Vue に依存しない。
2. `src/main`
   - 保存済み locale を起動時に確定し、各 renderer に必要な値だけを渡す。
   - OS ダイアログや main process 通知に同じカタログを使う。
3. `src/preload`
   - locale の読み取り専用情報または限定された設定変更 IPC だけを公開する。
   - Node.js API や任意ファイル読み込みを renderer に公開しない。
4. `src/renderer`
   - Vue コンポーネントは共通の翻訳関数を使う。
   - locale 変更時に main、assist、option の開いている画面を再描画する。

既存の `src/common/locale.ts` はゲーム用列挙値の表示と UI 文言が混在しているため、
一度に置換しない。意味を確認しながら新カタログへ段階的に移す。

## 段階

最初の milestone は `ja-JP` の型付きカタログと、開発時だけ使う文字長 200% の
擬似翻訳とする。審査担当が決まるまで、不完全な第 2 言語を利用者向け設定に表示しない。

### L10N-1: 棚卸しと基盤

- app-owned、game-owned、user-owned、external の文字列分類表を作る。
- 型付き key、`ja-JP` カタログ、fallback、補間、`Intl` helper を追加する。
- `GlobalSetting` に後方互換な locale フィールドを追加する。
- 欠落 key、余分な key、不正な補間変数を検出するテストを追加する。

現在の作業ツリーでは、型付き key、厳格な名前付き補間、`ja-JP` fallback、
利用者が選択できない `en-XA` 擬似翻訳、後方互換な `GlobalSetting.locale` を
`src/common/localization.ts` に実装済みである。数値、日時、相対時刻、複数形の
`Intl` helper も追加し、非有限数と無効な日時を拒否する。

main renderer と assist renderer の翻訳関数は、ストリームで同期される
`GlobalSetting.locale` を実行時に参照する。独立した option renderer は起動時の
`OptionData` で同じ確定済み locale を受け取る。最初の移行範囲として、タイトルバーの
主要操作、録画・スクリーンショット通知、アプリ情報画面のキャッシュ・データ保存先状態、
設定画面の全 app-owned 文言をカタログへ移行した。設定ウインドウのタイトルと、
キャプチャ・拡張機能フォルダを選択する main process のダイアログも同じ locale を使う。
URL、Proxy プロトコル、ポート番号、ユーザーのパスは翻訳値に含めず、技術値または
ユーザー所有値のまま表示する。

更新チェックは、`UpdateStateSnapshot` からボタン、主状態、副状態を生成する純粋な
`src/renderer/src/common/update-view.ts` に文言選択を分離した。idle、checking、
available、latest、updating、ready、error の全状態、バージョン、進捗率、
エラーコードを同じ型付きカタログで書式化する。更新 API の呼び出し、ダウンロード、
再起動処理は変更しない。

アプリ情報画面は、アプリ名、バージョン、説明、更新、キャッシュ、表示設定、記録データ、
情報提供、開発者向け、ライセンスの全 app-owned 文言を移行した。公式 URL、艦ログ、
艦これ、バージョン番号、保存先、ライセンス一覧は外部・技術・ユーザー所有値として
原値を残し、必要な周辺文言だけをカタログから生成する。タイトルバー色の保存値は
`TitlebarColor` のまま維持し、日本語ラベルを設定モデルから renderer の表示モデルへ
分離した。

公開ページ名とパネル名は、安定したページ ID・パネル名に対応する
`navigation.*` key から実行時に解決する。クラシック表示のタブ、workspace のページタブと
パネル見出し、独立 assist ウインドウのページ選択、パネルエラー見出しは同じ定義を使う。
既存レイアウトの保存形式と日本語の互換既定値は変更せず、利用者が作成または変更した
ページ名は locale を切り替えても原値を表示する。

共通の waiting/loading/empty/error/retry 表示は `status.*` と `common.*` key へ
移行した。戦果、戦闘履歴、ドロップ、当月戦果、資源記録、一覧の空状態、workspace の
空ページ、起動前案内、assist パネルのエラー境界を同じ実行時 translator へ接続する。
外部 DOM を管理する Highcharts の no-data 文言は locale 変更時に chart options も
更新する。艦名などのゲーム由来値と処理 phase などの技術値は名前付きパラメーターで
原値を維持する。任務キャッシュや審査済み知識グラフの周辺説明は任務固有の業務文言として
L10N-3 で移行した。

全 app-owned 文言の許可リスト方式監査は L10N-4 で実装した。option renderer も
限定された preload の locale 変更イベントを購読し、開いたまま locale を変更した場合に
再描画する。公開する第 2 言語は未実装である。

### L10N-2: アプリ shell と設定

- タイトルバー、ページ名、共通 loading/error/empty、アプリ情報を移行する。
- option renderer、更新確認、保存先、Proxy、録画設定を移行する。
- main/assist/option 間の locale 同期と再起動後の復元を確認する。

現在はタイトルバーの主要操作、録画・スクリーンショット通知、アプリ情報画面の全体、
option renderer の全表示文言と関連するフォルダ選択ダイアログまで移行済みである。
更新確認の状態・操作・設定文言も移行済みである。公開ページ名とパネル名も移行済みで、
共通 waiting/loading/empty/error/retry 表示も移行済みである。業務パネルは L10N-3 で
移行済みであり、残る app-owned 文言は L10N-4 の全体監査で扱う。

### L10N-3: 業務パネル

- 運用、戦闘・装備、ドロップ、任務の順に移行する。
- ゲーム由来名称を翻訳対象から除外したまま、周辺ラベルだけを切り替える。
- 任務条件の動的文言は構造化データから locale 別 formatter で生成する。

運用ページは、編成、遠征チェック、資源記録と、それらが直接表示する艦娘詳細、
遠征状態、資源・資材チャートの app-owned 文言を `operation.*` key へ移行済みである。
艦隊番号、速力、射程、特殊攻撃、カットイン、遠征判定は数値 enum から locale 別表示へ
解決し、表示済みの日本語をロジック key として再利用しない。翻訳結果を既存の計算結果
HTML に挿入する箇所は HTML エスケープを通す。艦名、装備名、遠征名、海域名は
game-owned の原文として維持し、数値、時刻、確率も翻訳対象の周辺ラベルと分離する。
Highcharts が管理する no-data と期間ボタンは locale 変更時に外部 DOM も更新する。

戦闘・装備ページも、戦果、戦闘履歴、艦船一覧、装備一覧、アイテム一覧と、それらが
直接表示する戦闘マップまで `battleEquipment.*` key へ移行済みである。陣形、制空状態、
戦術、航空偵察結果、装備射程・レア度、曜日は数値から locale 別表示へ解決し、艦名、
装備名、海域名、任務名、敵艦隊名は game-owned の原文として維持する。Highcharts の
系列名、軸ラベル、tooltip は locale 変更時に再構築し、翻訳結果と game-owned 名称を
HTML に挿入する箇所はエスケープを通す。

ドロップページも、マップ別、艦名別、セル詳細、艦種・勝利ランクの Highcharts 表示まで
`drop.*` key へ移行済みである。集約艦種とレア度は数値 enum から locale 別表示へ解決し、
艦名、海域名、イベント名は game-owned の原文として維持する。Highcharts の series、
tooltip、data label は locale 変更時に更新し、HTML formatter に挿入する名称は
エスケープを通す。

任務ページも、任務一覧、任務指引、絞り込み、目標計画、準備状況、根拠表示を
`quest.*` key へ移行済みである。任務カテゴリ、種別、周期、進捗、艦隊・旗艦・装備条件は
安定した enum や構造化条件から locale 別 formatter で生成する。構造化できない進捗も
旧来の日本語 HTML formatter へ戻さず、locale 別の件数表示へ安全にフォールバックする。
HTML に挿入する生成ラベルはエスケープを通す。

サーバーから受け取る任務名・説明、艦名、装備名は game-owned の原文として維持する。
審査済み知識の出典別 review note は根拠資料の本文として原値を維持し、出典ラベル、
競合要約、準備理由、注意事項などアプリが生成する周辺文言だけを locale 別に解決する。
これにより L10N-3 の 4 業務パネル移行は完了し、後続は L10N-4 の完了ゲートとなる。

### L10N-4: 完了ゲート

- Electron main の利用者向けダイアログと通知を移行する。
- app-owned の生文字列を許可リスト方式で監査する。
- 全対応 locale で component test と Electron レイアウト smoke を実行する。
- 翻訳者向け key 追加・レビュー・更新手順を
  [`docs/localization-workflow.md`](localization-workflow.md) に文書化する。

L10N-4 は現在の作業ツリーで完了している。Electron main のメニュー、録画失敗、
CSV 保存・書き込みエラーを共通カタログへ移行し、保存済み locale の変更時には開いている
ウインドウのタイトルとメニューを更新する。option renderer へは正規化済み locale だけを
一方向通知し、preload は解除可能な購読 API 以外の Node.js 能力を公開しない。
ゲーム通信、WebView の要求・応答、
保存済み記録形式は変更していない。

`npm run check:l10n` は renderer の Vue SFC と Electron main の利用者向け日本語を
構文木で走査し、未審査の app-owned 生文字列、空の許可理由、重複、出現数不一致、
使われなくなった許可項目を拒否する。現在の許可リストは game-owned、external、
合成 fixture の 32 出現だけである。

公開 locale は引き続き `ja-JP` のみである。内部専用 `en-XA` は layout fixture と
明示的な smoke 引数が同時にある場合だけ renderer へ渡され、設定へ保存されない。
`npm run smoke:localization` は production Electron で可視コンポーネントが 200% の
擬似翻訳になったことを確認し、最小・Surface サイズの全表示対象 workspace ページで document overflow、
パネル逸脱、横方向 overflow、到達不能なページネーションを検査する。この検査で見つかった
艦船一覧の長いフィルター文言によるページネーション裁切も、フィルター領域をスクロール可能に
して最小表領域を確保することで解消した。通常の `ja-JP` は同じ production bundle で
1316×632、1440×928、1600×800、1756×900、1920×1200、両 display、幅広 workspace を通過した。

## 受け入れ条件

- 対応言語を選択すると、main、assist、option の app-owned 文言が同じ言語になる。
- 再起動後も選択が維持され、破損・未知 locale は日本語へ安全に戻る。
- 対応言語のカタログ key は `ja-JP` と完全一致する。
- 変数不足、未定義 key、HTML 注入、空の操作ラベルをテストが拒否する。
- 艦名、装備名、任務名などゲーム由来の原文が変更されない。
- 1316×632、1440×928、1600×800、1756×900、1920×1200 と幅広 workspace で、
  翻訳後のボタン、タブ、説明、ページネーションが到達可能である。
- 200% の擬似翻訳（文字長拡張）で document-level overflow が発生しない。
- キーボード操作とスクリーンリーダー用ラベルが表示言語と一致する。
- ゲーム通信、Proxy 動作、保存済み記録の形式を変更しない。

## 初期実装前に決めること

1. 最初に追加する言語と、その翻訳レビュー担当
2. 翻訳をリポジトリ内だけで管理するか、外部翻訳サービスを使うか
3. locale 変更を即時反映するか、初期リリースだけ再起動を要求するか
4. ゲーム用語の補助訳を将来扱うか、常に原文のみとするか
5. 不完全な言語を利用者へ公開する基準

## 非目標

- DMM・艦これ Web ページへの翻訳注入
- ゲーム通信またはレスポンスの変更
- 機械翻訳結果の無審査配布
- 翻訳 bundle からの JavaScript 実行
- 多言語化と同時の広範な UI 再設計
